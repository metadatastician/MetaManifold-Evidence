== Translation conventions

These apply to every row below; a row repeats a convention only where it
changes the reading.

. *Agda `Set` propositions become Lean `Prop`.* `_≤_`, `_≡_`, `Holds`,
  `Sound`, `VerdictView`, `InInterval`, `InBounds`, `Bounded`, `Present`,
  `Absent`, `PresenceAgrees`, `LatentsAgree` are `Prop` in Lean. A theorem
  statement asserts that its type is inhabited, and that reading is the same
  in both provers. Lean's `Prop` is proof-irrelevant and Lean's `Eq` has
  uniqueness of identity proofs; Agda (`--without-K`) has neither. No
  statement here quantifies over or compares two proofs of one of these
  types, so this changes no statement. Every equation is at `Nat`, `Verdict`,
  `List Nat` or a list of rows, all types with decidable equality, where
  uniqueness of identity proofs is a theorem in Agda too.
. *Types that carry data stay in `Type`.* `Candidate` and `ReadFibre` are
  Lean subtypes `{world : W // observe world = r ∧ E world}`: the world is
  data, the two proof components are `Prop`. Agda's
  `Σ W (λ world → (observe world ≡ r) × E world)` has proof-relevant
  components; at the counts instance both components are propositions in
  Agda as well (equality of naturals; `_≤_` on naturals), so the two types
  have the same elements up to equality of their worlds. `Σ A (λ a → B a)`
  with a propositional `B` (results of `interval⇒fibre`, `bounds⇒fibre`,
  `≤-diff`) becomes `{a : A // B a}`. `_⊎_` (used by `≤-total` to pick a
  world) becomes `Uplus`, an inductive in `Sort (max 1 u v)` with the same
  constructors `inj₁`/`inj₂`, so it can still choose data.
. *`×` of propositions becomes `∧`; `¬ A` is `A → ⊥` in Agda and `Not A`,
  i.e. `A → False`, in Lean; `⊥` becomes `False`, `⊥-elim` becomes
  `False.elim`.*
. *`_≤_` is the ported inductive `Le`, notation `≤ₐ`*, with the two Agda
  constructors `z≤n : 0 ≤ₐ n` and `s≤s : m ≤ₐ n → m + 1 ≤ₐ n + 1`. It is not
  Lean's `Nat.le` (constructors `refl`/`step`). Lean writes `suc m` as
  `m + 1`, which is definitionally `Nat.succ m`; Agda's `suc zero` is Lean's
  literal `1`, definitionally `Nat.succ 0`.
. *Agda's builtin naturals map to Lean core's.* `Nat`, `zero`, `suc`; `_+_` is
  `Nat.add`, the truncated `_-_` is `Nat.sub`, the Boolean `_<_` is
  `Nat.blt`, the Boolean `_==_` is `Nat.beq`. Each pair is the same function
  on the naturals, so no statement changes. The *equations that hold by
  definition* differ: Agda's `_+_` recurses on its first argument, Lean's
  `Nat.add` on its second. So `+-zero` and `+-suc` are `rfl` in Lean, and the
  Agda definitional facts `0 + a = a`, `suc a + b = suc (a + b)`,
  `0 - suc m = 0`, `suc n - suc m = n - m`, `0 < suc b = true` are Lean
  helper lemmas (`zero-+`, `suc-+`, `zero-∸`, `suc-∸-suc`, `zero-<-suc`).
. *`Int` is the ported inductive* `ResidualEvidence.Int` with constructors
  `pos`/`negsuc`, as `Agda.Builtin.Int`, not Lean's `Int`, so every checker
  function computes by the same clauses.
. *Universe levels.* Agda's level-polymorphic `Candidate`, `Case`, `Holds`
  over `W : Set w`, `O : Set o`, `E : W → Set e`, `P : W → Set p` are Lean
  definitions over `W : Type u`, `O : Type v`, `E : W → Prop`,
  `P : W → Prop`. The Lean versions are less general (evidence and claims are
  propositions); every use in the counts theorems instantiates
  `E = Bounded n` and `P = Present | Absent`, which are propositions in both.
  `subst` and `upto6` likewise take a `Prop`-valued motive in Lean where
  Agda's takes `Set p`; both are only used at propositional motives here.
. *Implicit and explicit arguments are kept as in Agda* (`{y n}` stays
  implicit, `∀ y n →` stays explicit), except where a row says otherwise.
. *Names.* Every Agda name is kept, as a Lean quoted identifier where Agda's
  spelling is not a Lean identifier (`«fibre⇒interval»`, `«≤-trans»`,
  `«case»`). Declarations live under `MetaManifoldEvidence.<Module>`; the
  vocabulary port lives under `MetaManifoldEvidence.ResidualEvidence` and the
  checker under `MetaManifoldEvidence.ResidualEvidence.Checker`.
. *Proofs are not transcribed.* Lean's match compiler, when a pattern on a
  `≤ₐ` proof forces a non-variable index (for example `s≤s p` against
  `a + 1 ≤ₐ b + 1`), proves the index equations with `Nat.succ.injEq`, which
  rests on `propext`. The Lean proofs therefore split on the naturals and
  invert `≤ₐ` through two eliminator lemmas with variable indices
  (`≤-pred`, `≤-zero`). This is why the proofs differ from the Agda ones
  while the statements do not.

== Expected rejections

`scripts/check-lean.sh` demands that each file under `lean/reject/` fails to
elaborate with a type error located on its `theorem invalid` line, and with
no unknown name, parse error or resource limit. The first five mirror
`agda/reject/`.

| File | Invalid statement

`lean/control/AxiomGate.lean` is a gate self-test, not a rejection: the check
demands that its axiom audit flags a theorem that rests on `propext` and
passes one that rests on nothing.

== What this leg does not establish

* It does not check that the Lean and Agda statements are the same
  proposition by machine. The correspondence above is by reading, by the
  author of the Lean files; it has not been reviewed independently.
* The vocabulary port (`lean/ResidualEvidence.lean`) is transcribed from the
  Agda source and checked against it by reading. See the next section for
  what the explorer correspondence adds.
* The `.olean` files were not re-checked by an independent kernel checker.

== What the explorer correspondence shows

residual-evidence-types proves its Agda checker against the explorer by
`checker-matches-explorer : table ≡ ExplorerTable.expected`, over all 546
configurations the explorer emits (residual −6..6, noise bound 0..6, the
exact, sign and magnitude views, `assumeZero` false and true). The Lean leg
proves `table = expected` for the *ported* checker against the *same* table,
generated from the same Agda file at the pinned commit.

So the Agda checker and the Lean port compute the same row (candidate count,
presence verdict, identification status and latent values) on every one of
those 546 configurations, and in particular the same `presence` and the same
`latents` on the 49 cells of the counts bridge.

This is agreement on that table, not a proof that the two definitions are
equal. No prover compares the Agda and Lean definitions as functions, and
nothing here constrains either checker on a configuration the explorer does
not emit (a residual or bound outside the table, or a list of worlds that is
not `enumerate` of a configuration).
